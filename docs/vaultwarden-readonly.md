# Vaultwarden 登录、同步与个人写入

本文沿用原文件名。完整实现状态以 [API 覆盖矩阵](vaultwarden-api-coverage.md) 为准；整卡仍未完成。

## 支持范围

- 自定义 Vaultwarden 服务地址，支持部署在 URL 子路径。
- HTTPS 和正常证书校验；仅 localhost、127.0.0.1、::1 的本机测试允许 HTTP。
- 邮箱 / 主密码登录，PBKDF2-SHA256 或 Argon2id，TOTP 双重验证。
- 访问令牌刷新、手动全量同步、完整服务器加密文档、独立条目密钥。
- 个人八类型标准字段新增/编辑、密码历史维护和显式明文查看、多个网址及匹配策略/加密 checksum、文本/隐藏/布尔/关联自定义字段、收藏、文件夹管理和筛选、归档、软删除、恢复和永久删除；批量操作同步逐项核对，清回收站只选择deleted项目。
- 完整文档和个人登录填充投影分别进入 AES-GCM / Keychain 保护的本机快照。
- 主窗口分类/搜索/离线解锁/编辑，系统 Credential Provider 填充。

标准八类个人复制及受限的明文文件导入导出已接入：兼容 JSON 对照固定官方格式；MyGo `.mygovault` 保存八类及标准字段、历史和文件夹，导入会生成新密钥、新项目与新时间戳，并恢复归档/回收站归属。附件、通行密钥和未知扩展拒绝有损转换。含这些数据的完整复制/备份、组织导入导出、组织解密/管理、附件、Send、账号安全和其他登录provider等尚未完成。布尔/关联自定义字段可以编辑，未知关联ID保留；reprompt条目拒绝打开，待实现主密码再次验证。密码/TOTP安全复制、TOTP码生成及passkey交互未完成。网址的起始部分/正则表达式匹配可保存，但当前AutoFill不支持，不能宣称具备这些填充规则。双重验证支持指登录 Vaultwarden 时使用 TOTP 验证器代码。

真实集成测试使用 Vaultwarden 1.37.4；客户端请求以 `2025.12.0` 作为明确的协议兼容基线头，产品自身 User-Agent 和设备名称仍是 MyGo Vaultwarden。

## 加密兼容

实现位于 `internal/vaultwarden`，基础算法使用 Go 标准库和 `golang.org/x/crypto`。使用 Bitwarden `sdk-internal/bitwarden-crypto` 的公开固定向量核对派生和认证哈希。

1. 邮箱去除首尾空白并转小写；主密码按原始 UTF-8 字节使用，不去空格或做 Unicode 归一化。
2. PBKDF2 以邮箱作为盐；Argon2id 以邮箱的 SHA-256 作为盐，版本 0x13，memory 参数从 MiB 转为 KiB。
3. 登录验证值是对派生主密钥再执行一次 PBKDF2，盐为主密码，最后 Base64 编码。原始主密码不发送到服务器。
4. 用 HKDF-Expand 分别以 `enc` 和 `mac` 扩展主密钥；不额外做 HKDF-Extract。
5. 解密受保护用户密钥；条目带独立 key 时先解密该 key，再解密字段。
6. 类型 2 cipher string 按 `IV | ciphertext | HMAC` 解析，先验证 HMAC-SHA256，再解密 AES-256-CBC 并严格检查 PKCS#7 padding。

当前只接受经过认证的类型 2 cipher string 和 64-byte CBC/HMAC 用户/条目密钥。旧类型 0、类型 1、新 COSE 类型 7 或未知格式会明确失败，不推测格式或跳过完整性校验。

本次审计的 KDF 集成策略为：在线 PBKDF2-SHA256 接受 100,000–2,000,000 次，低于 100,000 时明确拒绝派生和发送登录证明，并引导先使用官方客户端提升账号 KDF。旧本地快照仍需兼容 5,000 次起的离线参数，不能把离线兼容范围当成在线许可。Argon2id 保持 2–10 次、1–16 lanes，内存上限调整为 1024 MiB（下限 16 MiB）。超出范围应报错，不截断服务端参数或换用较弱算法。这些边界由 auth 组件实现，最终集成须核对拒绝前无 HTTP 登录证明及边界回归；此段记录目标策略，不代替合入后的执行证据。

## 会话和身份

当前只支持一个活动账号。

在登录页填写服务器、邮箱和主密码后，点击“登录并同步”会先撤销本机此前的快照，再发起登录；若服务器要求 TOTP，主窗口直接切换到两步验证表单。取消登录或输错密码不会恢复此前账号的缓存；服务器数据不受影响。这个行为在登录按钮上方提示。

输入主密码后，提交会清空页面字段，并将有界 UTF-8 字节交给后台登录任务；收到首个 MFA 挑战或 `Login` 返回时清理该字节缓冲。派生主密钥和登录哈希只保留到登录/MFA 流程结束，整个登录流程最多等待 5 分钟。access token 只保留在解锁后的进程内存中。成功登录同步后，refresh token、设备标识、规范化服务器/账号/邮箱、受保护用户密钥标识、用户密钥及快照包装密钥编码成有版本的会话数据，存入快照的 AES-GCM 加密 payload；原始主密码、派生主密钥和登录哈希不持久化。锁定只清除内存会话，主密码或系统认证解锁后恢复已保存的会话；首次同步用 refresh token 换取新的 access token，无需主密码或 TOTP。退出登录、切换账号或服务器撤销凭据时会清理本机保存的会话。系统填充继续要求系统认证。

旧版快照没有保存会话时仍能解锁查看，点击“同步”会打开登录页并说明需登录一次。只是打开该页面不会撤销快照。

登录成功后，使用已派生主密钥，经 HKDF-Expand-SHA256（`mygo-vaultwarden/snapshot-unlock/v1`）生成独立的 32-byte 快照包装密钥。每次同步将包装密钥的临时副本和公开 KDF 参数交给 Swift，由其 AES-GCM 包装随机快照密钥；传输后清理副本。离线解锁按快照中的邮箱和有界 KDF 参数重新派生，解开随机快照密钥后读取当前快照，无需网络、TOTP 或 Keychain。主密码包装与系统认证是两个独立入口，原始主密码、主密钥及明文包装密钥均不落盘；具体格式见 [安全快照设计](secure-snapshots.md)。旧快照没有包装密文时，保留系统认证并提示重新登录一次。

一次同步绑定：规范化服务器 URL、登录邮箱、服务端稳定用户 ID，以及本地快照的预期 revision。后续 sync 返回其他账号或受保护用户密钥发生变化时，要求重新登录并尝试撤销原快照。

网络、协议或解密错误不会被当成成功空密码库。刷新失败、认证失效、身份变化与普通网络不可达分开处理。普通网络/解密错误保留上次成功快照并显示错误；成功同步才全量替换，包括移除服务端已删除的条目。

HTTP 不自动跟随重定向，避免把验证值或 bearer token 转发到其他地址；有响应体大小和超时限制。服务端返回的原始错误体不会直接显示或写入日志。

主密码和 TOTP 使用 MyGo 的 `TextInput.Password()` 遮掩显示，禁止复制/剪切输入内容。它们只作为当前表单的临时字段；提交、取消、返回和流程结束时清空，并更换输入子树的键，使下一次表单使用新的编辑器和撤销历史。验证码通过绑定登录代次的单次通道交给后台任务；取消会清理未消费的验证码，迟到挑战不会覆盖新登录。密码库列表模型仅保存认证后的标题、用户名、网址及类型/分类/权限标记。秘密在打开编辑表单后才解密；表单在锁定、登出、切换账号或撤销时与内存完整库一同清除。MyGo 编辑器和 Swift/Go 运行时可能保留内存副本，因此不宣称能证明清零所有历史副本。

## AutoFill 投影排除规则

完整服务器加密文档保留所有条目。以下仅从个人 Login 的系统填充投影排除，不表示丢弃完整库文档：

- organizationId 非空的组织条目。
- 非 Login 类型。
- 需要重新输入主密码的 reprompt 条目，避免用普通设备认证绕过条目策略。
- 服务端标记为已删除或已归档的条目。
- `viewPassword=false` 的条目。

可读取的个人 Login 中，任一需要解密的字段或条目 key 校验失败，会使本次同步整体失败，避免把损坏数据作为一个“成功但缺项”的新快照。

编辑标准字段、TOTP秘钥及四类自定义字段时保持同一item key；FIDO2和未知扩展保留。无法重加密的格式明确拒绝，不能用编辑接口冒充复制/共享/密钥轮换。

个人写入要求当前认证的server/account及本地snapshot revision。草稿在同步替换后不会自动获得新revision；仅保存令牌且未替换库内容的checkpoint可推进草稿版本。冲突保留草稿，尚无自动合并/重基界面。传输失败、意外成功响应、5xx和写后取消按结果未知处理，不自动重试，表单禁用再次保存并提示同步核对。完整PUT携带原始服务端revision及archivedDate；服务端revision校验并非严格CAS。

## URI 与系统填充

- 默认/Base domain：Go 使用公共后缀列表求可注册域名，传给共享匹配层；公共后缀本身不会扩展为通配范围。
- Host：核对主机和端口；系统只提供域名、无法证明端口时不填充。
- Exact：只在系统提供完整 URL 且匹配时填充。
- Starts with、Regex、Never 和非 HTTP(S) 地址不建立填充规则，统计为未支持/禁用。
- 不使用等价域名配置扩大范围。
- 没有支持网址的条目可显示在本机列表中，但不会因为存在一个 `hosts` 字段而回退成宽松填充。

快速候选回调提供的是已注册身份，不是完整请求 URL 的证明。因此 Host / Exact 规则不发布到 QuickType 索引；它们依赖列表回调提供的实际来源。扩展支持搜索和分页，不会只让用户选择前几条匹配记录。

所有系统候选仍绑定随机 snapshot ID + 条目 ID。切换账号、同步、删除和登出后的旧候选不能复用到新快照。

## 并发与取消

网络操作使用 context 取消和 UI 操作代次；迟到响应不能覆盖新界面。两种离线解锁均核对请求的服务器、账号和 revision；主密码派生在后台进行，期间发生锁定、退出或账号切换时，迟到解锁结果不能恢复旧列表。通过认证的解锁可为已保存会话授予该快照版本的同步权。每个在线会话另有 `sessionRevision`，仅新鲜解锁、本会话成功发布或成功保存刷新令牌的回执可推进该版本；状态刷新、错误响应中的最新版本不授予写入权。版本冲突、外部锁定/登出/替换会清除会话和显示列表，连续重试同步也不能重新发布已撤销的账号。

refresh token 轮换后，`SyncWithCheckpoint` 必须先调用 `saveSession` 把新的会话加密保存，再请求 `/api/sync`。该操作在同一存储锁内验证 scope 与预期 revision，仅重加密 payload（使用新 nonce）并推进 revision，保留条目、快照 ID、密码包装和系统候选身份。保存失败立即停止后续网络请求；保存成功但下载失败时，UI 保留原列表并采用本会话获授权的新 revision。锁定、登出或账号切换使旧回执失效，不能借令牌刷新恢复撤销的写入权。

Swift 在同一文件锁内核对发布 lease 并捕获成功回执，避免把提交后另一进程的版本返回为本次发布的版本。即使快照为空，锁定也必须推进 revision，才能使尚在登录中的发布失效。

零条同步结果明确编码为 `credentials: []`，覆盖已有快照、轮换密钥、使旧 lease/候选身份失效，并以空数组替换系统索引。它与缺少或为 null 的服务端 `ciphers` 字段不同，后者是协议错误。

HTTP 与 KDF 工作在后台执行。PBKDF2/Argon2 运算本身不能即时中断，但有资源上限，结果在取消后不会继续发起登录请求或绕过快照版本检查。

索引确认、快照提交和旧密钥清理仍分开报告。`indexPending` 不等于密码库尚未保存；它表示系统候选的更新还未收到对应代次的成功回执。

## 测试

```sh
go test ./...
go vet ./...
swift test --package-path macos
```

真实服务集成测试只应运行在新建的隔离本机实例：

```sh
MYGO_VW_TEST_URL=http://127.0.0.1:32768 go test -count=1 -v ./internal/vaultwarden -run TestLiveVaultwarden
```

这个测试会创建随机 `@example.invalid` 账号和测试条目，并设置一个测试账号的 TOTP；其中一个账号还执行八类型新增、更新、归档、取消归档、软删、恢复和永久删除，文件夹CRUD、批量全部状态操作及400部分成功核对，布尔/关联字段往返。不要指向已有生产实例。注册fixture逻辑全部位于 `_test.go`；产品新增/编辑由独立类型化API提供。

可选 `MYGO_VW_FIXTURE_DIR` 保存仅用于测试的登录材料到指定目录，以便使用隔离的官方 CLI profile 核对同一条目。目录权限 0700，文件 0600；不提交这些文件。

生产构建不需要 Bitwarden CLI、Node 或 Docker。

## 当前边界

- 快照桥接单次输入/输出上限 4 MiB（包括完整sync的base64开销）；AutoFill投影最多10,000条，完整文档解析最多100,000条；超限失败且保留旧快照，不静默截断。
- 未做后台周期同步或推送通知；界面显示最近成功快照时间。
- refresh token 在认证后恢复并自动刷新；服务器撤销登录、凭据损坏或旧版缓存缺少会话时，仍需重新登录。
- 新加密格式、组织与更多 MFA 需后续单独实现和验证。
